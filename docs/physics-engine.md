# 共有物理エンジン（P3・P5）

2026-10-07。[設計メモ](physics-design.md)のP3とP5として、両版で共有する物理エンジン`client::physics`を作った。
1回の`tick`が、clientの自分のplayerの1 tickを再現する。版の違いは`VersionTable`の
`PhysicsConstants`と`PhysicsRules`だけで表す。通信や接続状態には触れない。

共通APIでは[継続操作](common-control.md)（P7）が使う。有限入力の移動（`start_predicted_path`）は従来の乾いた地形のモデルのまま。

## 対応範囲

| 項目 | 内容 |
| --- | --- |
| 地形の形状 | 衝突形状がblock stateだけで決まるすべてのblock（階段・ハーフブロック・柵・壁・板ガラス・雪・カーペット・耕地・葉・チェスト・ランタン・ドア・閉じたトラップドア等） |
| blockの係数 | 滑りやすさ（氷・氷塊・青氷）、速度係数（ソウルサンド・ハチミツ）、ジャンプ係数（ハチミツ） |
| block効果 | スライムの跳ね返りと減速、ベッドの跳ね返り、蜘蛛の巣・スイートベリーの足止め（1.21.11の「織り」効果を含む） |
| 支えのblock | 1.21.11の`mainSupportingBlockPos`（縁に立ったときにどのblockの摩擦を使うか）、柵・壁の上 |
| 操作 | 歩行・ジャンプ・しゃがみ（姿勢と箱の高さ、縁で止まる）・ダッシュ（開始と停止の条件、ダッシュジャンプ） |
| 押し出し | blockの中に入ったときのclientの押し出し |
| 属性・効果 | 移動速度（受信した修飾子＋clientのダッシュ修飾子。修飾子の適用順は各版のmapの順序を再現）、1.21.11の`jump_strength`・`step_height`・`gravity`・`sneaking_speed`・`movement_efficiency`・`water_movement_efficiency`、跳躍力上昇・低速落下・盲目・イルカの好意 |
| アイテムの使用 | 使用中の入力の縮小（1.16.1は×0.2、1.21.11は`use_effects`の`speed_multiplier`）とダッシュ開始の禁止（1.21.11は`can_sprint`がfalseのとき） |
| 液体（P5） | 水と溶岩の中の移動、流れによる押し（水位・落下中の水・周囲の面）、水面でのジャンプ、しゃがんで沈む、ダッシュでの泳ぎ（泳ぐ姿勢と視線による上下）、低い隙間での這う姿勢、岸に手をかけて上がる動き、水没（目の位置）、水の中での落下距離のリセット、水浸しのblock、海草 |

範囲外は、状態を変えずに`ErrorKind::Unsupported`で拒否する。

- 泡の柱。
- 登り（梯子・つる・足場、梯子の上の開いたトラップドア）。P4で扱う。
- 浮遊効果、飛行、乗車、エリトラ。
- ハチミツの壁を滑り降りる動き。
- 位置や周囲の状況で形が変わるblock（竹・鍾乳石の位置ずれ、足場・粉雪・液体、動いているピストン）。
- 下の「確認済みのblock効果」に入っていないblockの効果。
- 1 tickに1 block以上落ちている間の落下距離のリセット判定（虚空へ落ちる等）。

## 版の違い（液体）

| 項目 | 1.16.1 | 1.21.11 |
| --- | --- | --- |
| 溶岩の中 | 箱に重なる溶岩blockの`entityInside`で判定（直前の移動の結果） | 溶岩の水位が正（生成直後のtickを除く） |
| 溶岩の流れ | 水に触れていないときだけ | 常に |
| 目の水没 | 目の高さ−0.11111111で判定 | 目の高さで判定 |
| 泳ぎ始め | 水没中のダッシュ | 加えて足元が水 |
| 水中の加速の補正 | 深海探索者のレベル（`/3`） | `water_movement_efficiency`属性 |
| `Vec3`の長さ | floatの平方根、正規化の下限1e-4 | doubleの平方根、下限1e-5 |
| 微小な移動 | 世界の境界の形が常に衝突対象の先頭にあり、1e-7未満の移動は0になる | 近くにblockがなければそのまま |

## block効果の確認

blockごとの移動に関わる処理（中に入ったとき・上を歩いたとき・落ちたとき・着地後・衝突形状）を、
両版の公式サーバーから「どのクラスが実装しているか」として書き出した
（`data/client_api/movement_blocks-{版}.json`、`scripts/movement_oracle/run.py`）。
各クラスの処理を両版で読み、clientの移動への影響で分類した（`src/client/physics/blocks.rs`）。
新しい版や未確認のクラスは、自動的に「範囲外」になる。

| 処理 | 移動に影響しない（ダメージ・炎・音・redstone・server側だけの変化） | 再現する | 範囲外 |
| --- | --- | --- | --- |
| 中に入ったとき | 1.16.1の液体（溶岩なら「溶岩の中」を記録）、炎、感圧板、ボタン、サボテン、焚き火、作物、ディテクターレール、ホッパー、ピッチャー、トリップワイヤー、スイレンの葉、ウィザーローズ、カエルの卵、オープンアイブロッサム、大きなドリップリーフ | 蜘蛛の巣、スイートベリー、ハチミツ（滑り降りない場合） | 泡の柱、ポータル、大釜、粉雪 |
| 上を歩いたとき | マグマ、レッドストーン鉱石、カメの卵、スカルク、1.16.1の階段（元のblockに委ねる） | スライム | — |
| 着地後 | — | スライム、ベッド | — |
| 衝突形状 | 液体（playerには形がない）、鐘、大きなドリップリーフ、サボテン、コンポスター、柵・板ガラス、フェンスゲート、砥石、ハチミツ、書見台、苔のカーペット、泥、ピッチャー、スカルクシュリーカー、雪、ソウルサンド、壁、壁掛けの吊り看板 | — | 動いているピストン、足場、竹、粉雪 |

落ちたときの処理（`fallOn`）は、すべてダメージの計算かserver側だけの変化（耕地を踏み荒らす等）で、
clientの移動には影響しない。

## 検証

[比較基準](movement-oracle.md)の162場面（両版で計310回。うち液体30場面、アイテムの使用7場面）で、全tickの位置・速度・接地・横の衝突・
ダッシュ・しゃがみ・水中・泳ぎが公式実装と**bit単位で一致**した（`src/client/physics/oracle_tests.rs`）。

公式サーバー上で動かす比較基準に固有の注意:
- 耕地への着地は、server側だけで確率的に土へ変わる。clientはこれを予測しない（後でblockの更新を受け取る）ので、
  比較の場面では耕地の上を歩くだけにした。
